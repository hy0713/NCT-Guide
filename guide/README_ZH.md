# 攻略机制

## 使用

运行根目录 `start.bat`，点击页面顶部的 **攻略（含剧透）**，正常选择年份、候选人、搭档及难度即可。攻略默认关闭；开关保存在本机。它显示在游戏窗口下方，不会替你点击答案或访问州。中英文切换不重置进度；原版105种内置组合使用同一个分析器，社区MOD不启用分析。

## 源码确认的机制

依据 `static/js/campaign_trail.js` 中的 `A`、`F`、`o`、`nextQuestion` 和访问确认处理器：

- 答案的全国乘数、州乘数和议题立场变化是预设数据；全国效果也可能影响对手，不能只找给自己加分最多的记录。
- 议题立场综合候选人、搭档和历次答案的权重；州支持度还取决于该州的议题立场与权重，因此同一个答案对不同州的效果不同。
- 州访问加成是 `0.005 × max(0.1, 州基础乘数) × 访问倍率`，累积访问计入同一公式。这不是直接增加0.5个百分点。搭档本州另有原版加成。
- 原版 `F` 生成正态随机量。支持率包含多处随机乘数；显示民调还有额外噪声，普选票总量也波动。最终计票不能用一次民调精确预知。
- 原版多数模式按州分配选举人票；非赢家通吃州有原作简化公式，比例模式另有分配函数。攻略复制原作规则，不改成现实制度。
- 高级竞选模式还会有筹款、广告、时间分配、游说及对手访问等变化。本面板反映已生效的数据，不模拟未来管理操作。

因此，“答案效果固定”成立；“所有人物都有一条固定必胜路线”没有得到源码或测试的证明。

## 怎样推荐

`model.js` 是构建时从原版抽出的计票函数及必要辅助函数，不在浏览器运行 `eval`。它克隆输入，将自身闭包中的正态随机项设为0、普选票随机因子设为中值，然后保留其他计算。这是**无随机波动的参考预测**，不是严格数学期望或胜率。原版计票函数和随机流完全不动。

每个当前可见选项都追加到克隆答案列表中，重新计算全州支持度。当前页面的选项顺序会随机变化，因此推荐使用屏幕位置并在内部匹配稳定答案ID，不提供容易串题的固定“选A/B/C”。

在赢家通吃州，排序指标为 `选举人票 / (1 + exp(-领先最强对手的差距 / 0.02))` 之和；比例及非赢家通吃州用选举人票乘得票份额。它连续地重视竞争州，避免只按当前取整后的选举人票排序而忽略小幅改善。同分时以普选票改善排序。**0.02是攻略的平滑参数，不是测定的随机波动率；该指标不是额外选举人票，也不是胜率。**

访问推荐对所有州逐一比较多访问一次的边际变化，再列前五名。访问只影响一个州，单州优化重算与完整原版重算的等价性有单独测试。推荐可能包括守住险胜州；不必只访问落后州。

这是即时、逐题的启发式攻略：不会搜索整局所有路线、预知随机数、保证未来所有分支的全局最优。短期最有利的选择仍可能在未来题目中遇到更优替代路线。

## 历史与游戏策略

原有已校订的中文选项及“典故”说明继续可用，旁注内容、来源及政治语境不会因得分排序而改变。游戏给予加分不等于现实中的政策可行、道德评价、或人物真正持有的立场。

现实总统选举要求取得已任命选举人的多数；1844、1860等年份的票数和门槛不能一律套用今天的270票。[美国国家档案馆：第十二修正案](https://www.archives.gov/electoral-college/provisions)。多数州采用赢家通吃，缅因和内布拉斯加有选区分票机制，游戏的州级简化公式不等同于真实选区模型。[美国国家档案馆：选举人票分配](https://www.archives.gov/electoral-college/allocation)。以上摘要随文件离线保存，链接仅供自行查证。

全国普选票领先不保证总统当选；无人取得选举人票多数时，现实制度会进入国会应急选举。[美国国家档案馆：历史](https://www.archives.gov/electoral-college/history)、[第十二修正案](https://www.archives.gov/electoral-college/provisions)。游戏的 `tie` 应与“赢得总统职位”区分。华莱士等第三方候选人的僵局路线不能冒称直接胜选；纳德尔等组合也不保证能在普通难度赢得多数。

## 文件与维护

- `model.js`：生成的离线预测器；原作同仓库来源，不新增再发行许可。
- `guide.js`：可选面板、当前选项和访问排序、缓存及数据隔离。
- `guide.css`：保留原风格的局部布局适配。
- `messages.json`：攻略UI的中英文维护源，合并到原有语言包。
- `tools/build-guide.cjs`：从AST定位函数并记录来源SHA256；原作算法更新后再生成，禁止修改保护基线以掩盖变化。
- `install.py`：合并语言键及安装入口。`tools/make-packs.py` 重建原有UI包时也会保留攻略键。
- `tests/guide.cjs`：真实浏览器按推荐选择和访问，双语通关及开关对照。
- `tests/guide-model.cjs`：全105组合、三种模式和三种难度倍率的访问优化等价检查。
- `tests/guide-ui.cjs`：三个模式、持久化、键盘隔离、反馈隐藏及无访问剧本的实际界面测试。
- `tests/guide-results.json`、`guide-model-results.json`、`guide-ui-results.json`：实际执行报告；只有 `status: passed` 才表示该次完整测试完成。

安装见仓库根目录README。安装后在游戏目录重建：`node tools/build-guide.cjs`；测试需启动本地服务器：`node tests/guide.cjs`，模型专项：`node tests/guide-model.cjs`，界面专项：`node tests/guide-ui.cjs`。Chrome测试工具属于开发依赖，游玩不需要Node、联网翻译或外部服务。

## 实测结果

全105组合中英文各通关一次，共210局；五组另做攻略隐藏对照，共215局。固定种子1776的攻略路线结果为95胜、7负、3僵局；不是胜率或人人必胜证明。模型1890次访问对照与四组模式／键盘界面检查通过。首次并发批量测试曾发生加载失败，未把中断整轮冒称通过；顺序续跑及专项报告保留实际证据。完整逐组合结果见 [实测报告](TEST_REPORT_ZH.md)。

## 验证边界

具体通关数量、实际模式及结果以测试报告为准。固定种子通关证明流程和双语一致性，不能证明所有随机种子下必胜、全部历史策略已穷尽或攻略一定胜过所有人工路线。该功能没有调整难度、数值、选项关联、触发条件或选举算法。
